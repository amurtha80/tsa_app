#### Pi Cutover — "Chromote has been closed" During Retry Pass (FIXED 2026-08-14)
- 2026-08-14: Found while verifying the `quit()`-cascade fix above. Root cause:
  ATL/EWR/JFK/LGA all only closed their chromote session/default-object in a
  teardown block at the *bottom* of their function — which `safe_read_html_live()`'s
  `stop()` (added by the `quit()` fix) skips entirely on a failed page load,
  leaving an orphaned/broken default chromote object that the next chromote
  airport script in the same shared R session could reuse, producing cascading
  "Chromote has been closed" / port errors that look like site outages but are
  actually caused by our own teardown gap. Fixed by moving the teardown into an
  `on.exit()` registered at the top of each of the 4 chromote scripts, so it
  always runs regardless of success or failure. Verified live: with JFK's URL
  deliberately broken to force permanent failure, ATL/EWR/LGA all continued to
  scrape and write successfully across multiple cycles in the same run.
- Also removed `RSelenium` and `netstat` from the orchestrator's per-cycle
  package load (`scrape_data_automate.R`) — confirmed via grep that no active
  scraper uses either (only retired `archive/*_scrape_v1.R` versions do), so
  they were pure overhead loaded every 5 minutes right before the chromote
  scrapers run.
